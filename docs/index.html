🚀 RapidBase - Documentación para Agentes de Desarrollo

Esta documentación está diseñada específicamente para agentes de IA que necesitan comprender rápidamente la estructura, arquitectura y funcionalidades del proyecto RapidBase.

Propósito: RapidBase es un motor de base de datos performance-first con ORM, query builder avanzado, sistema de caché, autoloader inteligente, framework TDD integrado y framework para APIs autodescriptivas.

Estructura del Proyecto

/workspace/ ├── src/RapidBase/ # Núcleo del framework │ ├── Core/ # Motor principal (DB, Gateway, X, Q) │ ├── Api/ # Framework de APIs │ ├── Tdd/ # Framework TDD │ ├── Autoloader/ # Autoloader avanzado │ ├── ORM/ # ActiveRecord │ └── Cache/ # Sistema de caché ├── tests/ # Suite de pruebas (505 archivos) ├── examples/ # Ejemplos y demos │ └── querybrowser/ # Aplicación demo completa └── docs/ # Documentación existente
Ver Core Ver API Ver TDD Ver QueryBrowser

🏗️ Arquitectura del Sistema

Flujo de Ejecución Típico

  1. DB.php / X.php → Fachadas públicas que reciben llamadas del usuario
  2. Gateway.php → Pasarela intermedia con eventos, caché y logging
  3. Q.php → QueryBuilder que construye SQL con características avanzadas
  4. Executor.php → Ejecuta queries contra la base de datos
  5. Conn.php → Gestiona conexiones PDO
Nota importante: DB.php es más rápido que X.php porque es una fachada más directa. X.php ofrece aislamiento de conexiones pero con overhead adicional.

Componentes Principales

Componente Ubicación Propósito
Q.php Core/SQL/ QueryBuilder con autojoin, matrices de condiciones, sorters compactos
Gateway.php Core/ Pasarela central con eventos, caché, logging y estadísticas
DB.php Core/ Fachada directa y rápida para operaciones CRUD
X.php Core/ Fachada con aislamiento de conexiones (más lenta pero flexible)
CacheService Core/Cache/ Sistema de caché multi-adapter (Redis, Memcached, SQLite, etc.)

⚡ Inicio Rápido

Configuración Básica

<?php
use RapidBase\Core\DB;

// Configurar conexión
DB::setup('sqlite:database.db', '', '');

// Query simple
$users = DB::select('users', ['status' => 'active']);

// Query con matriz de condiciones
$users = DB::select('users', [
    ['role' => 'admin', 'status' => 'active'],
    ['role' => 'moderator', 'verified' => true]
]);
Ventaja clave: La sintaxis de matriz permite expresar lógica booleana compleja de forma compacta sin closures anidadas.

Q.php - QueryBuilder Avanzado Core

Ubicación: src/RapidBase/Core/SQL/Q.php

Q.php no es un típico fluent query builder. Implementa características únicas:

Características Principales

  • Auto-Join Progresivo: Detecta automáticamente las tablas necesarias basado en los campos solicitados
  • Matriz de Condiciones: Sintaxis visual para lógica booleana compleja
  • Sorters Compactos: Definición de ordenamiento con sintaxis ultra-corta
  • Paginación Nativa: Usa números de página en lugar de offset manual

Ejemplo: Matriz de Condiciones

// Encontrar usuarios que son:
// (Admins AND activos) OR (Moderadores AND verificados)

DB::select('users', [
    [ 'role' => 'admin', 'status' => 'active' ],
    [ 'role' => 'moderator', 'verified' => true ]
]);

// SQL generado:
// WHERE (role='admin' AND status='active') 
//    OR (role='moderator' AND verified=1)

Ejemplo: Sorters Compactos

// Ordenar por fecha ASC, precio DESC
'order' => ['date', '-price']

// Ordenar por índice de columna (útil para COUNT, SUM)
'select' => 'category, COUNT(*) as total',
'order' => [2, -1]  // ORDER BY total ASC, category DESC
Niveles de Auto-Join:
  • auto - Detección automática basada en schema
  • manual - Developer define exactamente qué joins usar
  • off - SQL estándar sin magia

Gateway.php - Pasarela Central Core

Ubicación: src/RapidBase/Core/Gateway.php

Gateway es un punto intermedio, una pasarela que permite tener eventos, caché y es un cuello de botella por donde pasan las llamadas.

Responsabilidades

  • Gestión de eventos pre/post ejecución
  • Integración con CacheService
  • Logging de estadísticas y performance
  • Normalización de respuestas
  • Manejo de transacciones

Flujo de Datos

DB::select() / X::select()
        ↓
   Gateway.select()
        ↓
   Q.build() → SQL
        ↓
   Executor.run()
        ↓
   CacheService (opcional)
        ↓
   QueryResponse
Importante: Gateway es el cuello de botella intencional. Todas las optimizaciones de caché y eventos deben pasar por aquí para mantener consistencia.

DB.php - Fachada Directa Core

Ubicación: src/RapidBase/Core/DB.php

DB.php es una fachada más directa que usa Gateway. Es más rápida que X.php pero ofrece menos control sobre aislamiento de conexiones.

Métodos Principales

setup($dsn, $user, $pass, $name = 'main')

Configura una conexión y realiza auto-descubrimiento del schema

select($table, $where = [], $fields = '*', ...)

Query SELECT con todas las características avanzadas de Q.php

insert($table, $data)

INSERT directo retornando lastId

update($table, $data, $where)

UPDATE con soporte para matriz de condiciones

Ejemplo de Uso

<?php
use RapidBase\Core\DB;

// Configurar
DB::setup('mysql:host=localhost;dbname=mydb', 'user', 'pass');

// Select con paginación nativa
$result = DB::select('products', 
    ['category' => 'electronics'],  // where
    'id, name, price',              // fields
    null,                           // groupBy
    [],                             // having
    ['name', '-price'],             // sort
    3,                              // page number (no offset!)
    PDO::FETCH_NUM                  // fetch mode
);

echo "Página {$result['page']} de productos";

X.php - Executor con Aislamiento Core

Ubicación: src/RapidBase/Core/X.php

X.php es una fachada, un ejecutor que usa Gateway con la ventaja teórica de aislar las conexiones. Sin embargo, es más lenta que DB.php debido al overhead adicional.

Cuándo Usar X.php vs DB.php

Escenario Recomendación
Aplicación single-tenant DB.php (más rápido)
Multi-tenant con conexiones dinámicas X::con($tenantId)
Testing con múltiples bases de datos X::con('test_db')
API pública con aislamiento X::con($userId)

Ejemplo: Aislamiento de Conexiones

<?php
use RapidBase\Core\X;

// Crear executor para tenant específico
$tenant = X::con('tenant_123')
    ->connect('mysql:host=db1.example.com;dbname=tenant123', 'user', 'pass')
    ->from('users', ['status' => 'active']);

// Ejecutar query aislada
$users = $tenant->select();

// Cerrar conexión cuando se termine
$tenant->close();

Sistema de Caché Cache

Ubicación: src/RapidBase/Core/Cache/

Sistema de caché multi-adapter que soporta múltiples backends intercambiables.

Adapters Disponibles

  • MemoryCacheAdapter - Caché en memoria (volátil, rápido)
  • RedisCacheAdapter - Redis para producción
  • MemcachedCacheAdapter - Memcached alternativo
  • DirectoryCacheAdapter - Archivos en disco
  • SQLiteMemoryCacheAdapter - SQLite en memoria
  • SessionCacheAdapter - Sesión PHP

CountCache - Optimización Especial

CountCache es una implementación especializada para contar registros sin ejecutar COUNT() repetidamente. Mantiene contadores incrementales que se actualizan con INSERT/DELETE.

Ejemplo de Configuración

<?php
use RapidBase\Core\Cache\CacheService;
use RapidBase\Core\Cache\Adapters\RedisCacheAdapter;

// Configurar adapter
$adapter = new RedisCacheAdapter([
    'host' => 'localhost',
    'port' => 6379
]);

CacheService::setAdapter($adapter);

// Uso en queries
$result = DB::select('products', [], '*', null, [], [], 1, PDO::FETCH_NUM, null, true);
// El último parámetro (true) habilita caché automática

Autoloader Avanzado Core

Ubicación: src/RapidBase/Autoloader/Autoloader.php

No es un autoloader PSR-4 estándar. Incluye características avanzadas:

Características Únicas

  • Caché de rutas: Guarda mapeo clase→archivo para acelerar cargas futuras
  • Estadísticas de uso: Trackea qué clases se usan más
  • Preloading inteligente: Precarga clases frecuentemente usadas
  • Detección de dependencias: Sabe qué archivo usa qué clases
  • Búsqueda recursiva: Escanea directorios si no encuentra la clase

Ejemplo: Smart Preloading

<?php
use RapidBase\Autoloader\Autoloader;

$loader = Autoloader::getInstance('/path/to/src')
    ->enableStats(true)
    ->setPreloadThreshold(3)  // Preload después de 3 usos
    ->register();

// Después de varias ejecuciones, las clases usadas 
// frecuentemente se precargan automáticamente
$loader->preloadSmart();
Uso en QueryBrowser: El QueryBrowser usa una versión bundeada (RapidBase.php) que incluye el autoloader miniaturizado para evitar problemas con includes manuales.

API Framework API

Ubicación: src/RapidBase/Api/

Framework para crear APIs autodescriptivas con mínimo boilerplate. Los endpoints se descubren automáticamente y pueden ser testeados individualmente.

Componentes

  • ApiContext.php - Contexto de request (params, session, auth)
  • BaseEndpoint.php - Clase base para todos los endpoints

Creación de Endpoint

<?php
namespace RapidBase\Endpoints;

use RapidBase\Api\BaseEndpoint;

class UserService extends BaseEndpoint
{
    /**
     * Lista usuarios con filtros
     * @param string $role Filtro por rol
     * @return array Lista de usuarios
     */
    public function list($role = null)
    {
        $where = $role ? ['role' => $role] : [];
        return DB::select('users', $where);
    }

    /**
     * Crea nuevo usuario
     */
    public function create($data)
    {
        return ['id' => DB::insert('users', $data)];
    }
}

Auto-descripción

Cada endpoint expone automáticamente su catálogo vía describe(), version() y catalog(). El Magic Client de JavaScript usa esta metadata para permitir llamadas sin configuración previa.

Magic Client (JavaScript)

// ¡Sin configuración! El proxy detecta endpoints automáticamente
const api = new RapidBaseClient('api/v1/index.php');

// Se traduce a: ?ep=UserService&action=list&role=admin
const users = await api.userService.list({ role: 'admin' });

TDD Framework TDD

Ubicación: src/RapidBase/Tdd/

Framework propio de pruebas unitarias TDD, diseñado para trabajar sin dependencias externas.

Componentes

  • Runner.php - Ejecutor principal con auto-descubrimiento
  • TddRunner.php - Wrapper con reporting
  • TestCase.php - Clase base para tests
  • EnvironmentBuilder.php - Setup de entorno de testing

Características

  • Auto-descubrimiento: Detecta Models y Endpoints automáticamente
  • Generación de skeletons: Crea tests básicos desde reflexión
  • Reporting visual: Historial de tests con métricas de performance
  • Modos de ejecución: --all, --first, --failing, --scan

Ejemplo: Test de Endpoint

<?php
use RapidBase\Tdd\TestCase;

class UserServiceTest extends TestCase
{
    protected $endpoint = 'UserService';

    public function testList()
    {
        $response = $this->call('list', ['role' => 'admin']);
        
        $this->assertTrue($response['success']);
        $this->assertIsArray($response['data']);
    }
}

Comandos Útiles

# Ejecutar todos los tests
php tdd_runner.php --all

# Generar skeletons para nuevos endpoints
php tdd_runner.php --skeleton ../tests_informales

# Re-ejecutar solo los que fallaron
php tdd_runner.php --failing

# Ver reporte histórico
php tdd_report.php

ORM ActiveRecord ORM

Ubicación: src/RapidBase/ORM/ActiveRecord/

Implementación de ActiveRecord que usa PDO::FETCH_OBJ para hidratación eficiente.

Modelo Base

<?php
namespace RapidBase\ORM\ActiveRecord;

class Model
{
    // Métodos principales:
    // - find($id)
    // - save()
    // - delete()
    // - all()
    // - where($conditions)
}

Ejemplo de Modelo

<?php
use RapidBase\ORM\ActiveRecord\Model;

class User extends Model
{
    protected $table = 'users';
    
    // Validaciones automáticas
    protected $rules = [
        'email' => 'required|email|unique',
        'password' => 'required|min:6'
    ];
}

// Uso
$user = User::find(1);
echo $user->email;  // Acceso como propiedad

$users = User::where(['status' => 'active'])->get();

TDD Runner

Ubicación: tests/PoC/RapidBase/Tdd/Runner.php

El TDD Runner es el corazón del sistema de testing. Permite:

  • Descubrir automáticamente clases testeables
  • Generar esqueletos de test basados en reflexión
  • Ejecutar tests con detección inteligente de fallos
  • Generar reportes visuales de historial
Workflow recomendado:
  1. Crear Endpoint/Model
  2. Ejecutar --skeleton para generar test básico
  3. Refinar test con aserciones específicas
  4. Ejecutar --first para TDD iterativo
  5. Ver reporte con tdd_report.php

Tipos de Tests

Tests Unitarios

Prueban componentes individuales aislados. Ubicados en tests/Unit/.

Tests Funcionales

Validan flujos completos de negocio. Ubicados en tests/Functional/.

Tests de Performance

Benchmarks comparativos entre diferentes implementaciones. Incluyen:

  • FETCH_ASSOC vs FETCH_NUM
  • static vs dynamic calls
  • Hash algorithms benchmark

Pruebas de Estrés

Simulan carga pesada para detectar cuellos de botella. Ubicadas en tests/Stress/.

Características Únicas de RapidBase

Basado en docs/labs/unique_features_rapidbase.md, estas son las funcionalidades que distinguen a RapidBase de otros ORMs como Eloquent, Doctrine o Medoo.

1. Matrix Where

Sintaxis matricial para lógica booleana compleja sin closures anidadas. 

// (Admin AND active) OR (Moderator AND verified)
[
    ['role' => 'admin', 'status' => 'active'],
    ['role' => 'moderator', 'verified' => true]
]

2. Compact Ordering

Definición ultra-corta de ordenamiento con índices y prefijos. 

'order' => ['date', '-price', 2, -1]
// ORDER BY date ASC, price DESC, col2 ASC, col1 DESC

3. Smart Pagination

Paginación por número de página en lugar de offset manual. 

'page' => 3, 'limit' => 20
// Internally: LIMIT 20 OFFSET 40

4. Progressive Auto-Join

Detección automática de JOINs basada en schema con control granular.

5. Native Performance

Uso de PDO::FETCH_NUM por defecto para máxima eficiencia en memoria.

Comparativa: RapidBase tiene curva de aprendizaje ⭐ (muy baja) vs ⭐⭐⭐ de Eloquent y ⭐⭐⭐⭐ de Doctrine, mientras ofrece mejor performance.

Patrones de Diseño

  • Gateway Pattern: Gateway.php como punto único de entrada
  • Builder Pattern: Q.php para construcción de queries
  • Strategy Pattern: Adapters de caché intercambiables
  • Active Record: Model.php para ORM
  • Command Pattern: Endpoints como comandos ejecutables
