🐘 RapidBase con PostgreSQL – Tutorial de Conexión y Pruebas de Rendimiento

En este tutorial aprenderás a conectar RapidBase a una base de datos PostgreSQL, generar el mapa de esquema (schema map) y ejecutar una serie de pruebas de rendimiento que comparan RapidBase frente a PDO nativo.

Requisitos: PHP 8.1+, Composer, extensión PDO_PGSQL instalada, y acceso a un servidor PostgreSQL (usaremos localhost con la base de datos rapidbase_test, usuario rapidbase_user, contraseña rapidbase_pass).

1. Instalación y configuración básica

Si aún no tienes RapidBase, clona el repositorio o instálalo vía Composer. Luego, en tu script de inicio, configura la conexión con DB::setup().

<?php
require_once 'vendor/autoload.php';

use RapidBase\Core\DB;

DB::setup(
    'pgsql:host=localhost;port=5432;dbname=rapidbase_test',
    'rapidbase_user',
    'rapidbase_pass',
    'main'   // nombre de la conexión
);

2. Generación del mapa de esquema (schema map)

RapidBase utiliza un archivo schema_map.php que describe las tablas, columnas y relaciones de tu base de datos. Para PostgreSQL, podemos generarlo con la herramienta de línea de comandos.

php src/RapidBase/Cli/generate-schema.php pgsql "host=localhost;port=5432;dbname=rapidbase_test" rapidbase_user rapidbase_pass

Esto creará un fichero schema_map.php en el directorio actual. Cárgalo en tu aplicación:

use RapidBase\Core\SchemaMap;
SchemaMap::loadFromFile(__DIR__ . '/schema_map.php', 'main');

4. Código de cada prueba

4.1 INSERT individual

Inserta una sola fila usando los parámetros seguros de PDO y la misma operación con RapidBase.

// PDO nativo
$stmt = $pdo->prepare("INSERT INTO users (name, email) VALUES (?, ?)");
$stmt->execute(['John', 'john@example.com']);

// RapidBase (vía Gateway)
\RapidBase\Core\Gateway::action('insert', 'users', ['name' => 'John', 'email' => 'john@example.com']);

4.2 INSERT Batch (100 registros individuales)

Realiza 100 inserciones secuenciales, sin usar transacciones explícitas.

// PDO nativo (100 inserciones una tras otra)
for ($i=0; $i<100; $i++) {
    $stmt = $pdo->prepare("INSERT INTO users (name, email) VALUES (?, ?)");
    $stmt->execute(["Name$i", "email$i@example.com"]);
}

// RapidBase (100 llamadas a Gateway::action)
for ($i=0; $i<100; $i++) {
    \RapidBase\Core\Gateway::action('insert', 'users', ['name' => "Name$i", 'email' => "email$i@example.com"]);
}
Nota: En el caso de RapidBase, cada inserción genera un objeto CompiledQuery y una consulta preparada. Para inserción masiva, se recomienda usar Q::insert() con múltiples filas o Executor::batch().

4.3 INSERT múltiple nativo (una sola llamada con muchas filas)

Aquí aprovechamos la inserción masiva nativa de PostgreSQL: un único INSERT con múltiples VALUES.

// PDO (construir string SQL manualmente)
$rows = [];
for ($i=0; $i<100; $i++) {
    $rows[] = "('Name$i', 'email$i@example.com')";
}
$pdo->exec("INSERT INTO users (name, email) VALUES " . implode(',', $rows));

// RapidBase: Q::insert(array de arrays)
$data = [];
for ($i=0; $i<100; $i++) {
    $data[] = ['name' => "Name$i", 'email' => "email$i@example.com"];
}
\RapidBase\Core\SQL\Q::into('users')->insert($data)->run();

4.4 SELECT simple (sin WHERE)

// PDO
$stmt = $pdo->query("SELECT * FROM users");
$rows = $stmt->fetchAll(PDO::FETCH_ASSOC);

// RapidBase
$res = \RapidBase\Core\Gateway::select('*', 'users', [], [], [], [], 1, false, \PDO::FETCH_ASSOC);
$rows = $res['data'];

4.5 SELECT con WHERE

// PDO
$stmt = $pdo->prepare("SELECT * FROM users WHERE city = ?");
$stmt->execute(['New York']);
$rows = $stmt->fetchAll();

// RapidBase
$res = \RapidBase\Core\Gateway::select('*', 'users', ['city' => 'New York']);
$rows = $res['data'];

4.6 SELECT con JOIN

// PDO (join manual)
$stmt = $pdo->query("SELECT u.*, p.title FROM users u LEFT JOIN posts p ON u.id = p.user_id");
$rows = $stmt->fetchAll();

// RapidBase (auto‑join usando schema map)
$res = \RapidBase\Core\Gateway::select('*', ['users u', 'posts p'], ['u.id' => 'p.user_id']);
$rows = $res['data'];

4.7 UPDATE

// PDO
$stmt = $pdo->prepare("UPDATE users SET status = ? WHERE id = ?");
$stmt->execute(['active', 1]);

// RapidBase
\RapidBase\Core\Gateway::action('update', 'users', ['status' => 'active'], ['id' => 1]);

4.8 DELETE

// PDO
$stmt = $pdo->prepare("DELETE FROM users WHERE id = ?");
$stmt->execute([42]);

// RapidBase
\RapidBase\Core\Gateway::action('delete', 'users', ['id' => 42]);

4.9 COUNT

// PDO
$stmt = $pdo->query("SELECT COUNT(*) FROM users");
$count = (int) $stmt->fetchColumn();

// RapidBase
$count = \RapidBase\Core\Gateway::count('users');

4.10 Transacción (10 INSERTs)

// PDO
$pdo->beginTransaction();
for ($i=0; $i<10; $i++) {
    $stmt = $pdo->prepare("INSERT INTO users (name) VALUES (?)");
    $stmt->execute(["Name$i"]);
}
$pdo->commit();

// RapidBase
\RapidBase\Core\Executor::transaction(function() {
    for ($i=0; $i<10; $i++) {
        \RapidBase\Core\Gateway::action('insert', 'users', ['name' => "Name$i"]);
    }
});

5. Interpretación

  • Consultas de lectura (SELECT, COUNT) prácticamente empatan con PDO (diferencia inferior al 10 %).
  • Escrituras simples (INSERT, UPDATE, DELETE) son más rápidas gracias a la optimización del Query Builder y la ausencia de overhead.
  • Operaciones masivas (INSERT batch con múltiples consultas) se benefician de usar el método nativo Q::insert() con múltiples filas. La prueba de «INSERT múltiple nativo» demuestra que RapidBase es 3.5 veces más rápido que el PDO equivalente.
  • El overhead adicional en transacciones se debe a la creación de objetos CompiledQuery en cada iteración; puede compensarse utilizando Executor::batch() para ejecutar la misma sentencia con distintos parámetros.

Con el mapa de esquema correcto, RapidBase ofrece un rendimiento comparable a PDO y añade comodidad, seguridad y auto‑joins sin sacrificar velocidad.
